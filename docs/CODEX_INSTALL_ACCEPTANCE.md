# Codex 安装初始文档验收

安装入口为根目录 `INSTALL.md`，技术安装由 `scripts/setup-codex.mjs` 执行。安装初始化包可由 `scripts/build-install-kit.mjs` 按明确白名单构建，不包含用户资料、认证文件或环境配置。

本次使用 Windows 本机 Codex 原生 CLI，在独立临时 Codex home、合成资料库和非正式服务端口测试。不会向真实记忆写入样例，也不复制真实登录信息或替用户信任 Hook。

## 验收范围

- 从文档安装实际原生插件，核对 ID、版本、安装目录和发布文件。
- 从已安装路径启动真实 MCP stdio，完成初始化、工具发现和记忆读取。
- 读回安装前已存在的获准合成记忆，保留 ID、版本与内容；未授权私密条目继续不可读。
- 再次运行安装器，验证版本复用和资料保留。
- 检查实际 Hook 定义及待信任状态，不声称自动执行已经获得信任。
- 从独立安装包重复同一流程，验证无需原开发目录。

## 实际结果 · 2026-11-17

| 验收项 | 结果 |

安装器针对性测试 **10/10 通过**；最终全量自动测试 **960/960 通过**，语法检查通过。全量首轮有一个已有 HTTP 测试出现 `fetch failed / bad port`，该文件复验及最终全量复验通过；首轮日志单独保留，未修改该用例。

完整机器回执保存在开发工作区的 `artifacts/codex-install-document-acceptance.json`，最终测试日志为 `artifacts/tests-codex-install-document.txt`。发行包携带本页验收摘要，不包含测试资料库。

## 当前产品边界

当前需要系统 Node.js 20+，本包没有私有 Node 运行时。固定版本安装包与校验值由本仓库的 GitHub Release 提供。跨平台源码包含在包内，本轮实际执行环境为 Windows；未执行的系统不标记通过。无真实登录的隔离环境能够验证原生插件安装和 MCP 调用，不能证明新聊天中的模型已主动使用技能。平台 Hook 信任保持真实状态。

个人主页的返回 URL 与 HTTP 页面已核对，本轮未做视觉打开验收。真实用户资料库、登录凭据和 Hook 信任未作为测试输入。
